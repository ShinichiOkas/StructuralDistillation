## 0. 何を根拠に書いているか

根拠は 3 つだけ: **師匠の言葉（原文）**・README・`LESSONS_FROM_THE_FIRST_CONSUMER.md` の実測。
どれにも辿れない項目は「⚠ AI 判断」と明記する。他のプロジェクトは参照していない（師匠の規則）。

### 師匠の言葉（原文・2026-09-21）

> このプロジェクトは、入力した命題に対して客観的判定を行うこと。そして判定出力（スカラー）を適切な分布の連続量ないし離散値として得られること。
> その方法として内部的には対立を含む複数の問いに対してLLMで答えさせ、その分布から出力値を作るというコンセプト。
> それが実現できる汎用ライブラリであること。

> 例えば「羅生門」において「老婆は悪人である」の度合いを１～５で示せ。というような命題に対して答えが出ること。

> 基本的には判定に必要な全文を入力する（LLMの知識に頼らない）。
> 問いの集合もLLMが生成することを基本と考える。よって問いの生成ルールやそれを規定するハーネスもこのプロジェクトに含まれる。
> 適切な分布は(b) 一つの出力が幅を伴って返ることを示す。
> その分布の確からしさ、コンフィデンスレベルも添えられればなおよい。
> 対立を含むは、LLMの偏りを打ち消すことを目的とする。Y,N両方の観点から問い、Y,Nが割れるのか、偏るのかを判定する。なので軸の撮り方は命題次第。

## 1. 一行で

> **本文と命題を受け取り、支持・反証の両観点から問いの集合を LLM に立てさせ、各問いを本文の根拠つきで答えさせ、
> その答えの分布から「度合い ＋ 幅 ＋ 確からしさ」を、宣言した型の中で返す。**

羅生門の例で言えば: 本文（全文）と「老婆は悪人である」と「1〜5」を渡す →
「老婆は死体から髪を抜いたか」（支持観点）「老婆は生きるためにやむを得ずしたか」（反証観点）…という問いが立つ →
各問いに Yes / No / 判定不能 と引用が返る → 支持 s 軸・反証 r 軸から度合いの分布が出る → 1〜5 の段と各段の確率が返る。

## 2. 用語（師匠の語彙を正とする）

| 語 | 意味 |
|---|---|
| **命題** | 判定したい主張。自然言語 1 文（例: 「老婆は悪人である」） |
| **本文** | 判定に必要な全文。LLM の知識に頼らず、ここに無いことは判定不能 |
| **問い** | 本文の内容について Yes / No で答えられる 1 文。LLM が命題から生成する |
| **軸** | 問いが捉える観点。1 軸 = 1 問い（v1）。**軸の取り方は命題次第** |
| **観点（Y / N）** | 問いを立てた側。**支持観点**の問いは Yes が命題を支持し、**反証観点**の問いは Yes が命題を反証する |
| **対立** | 両観点の問いを同数含めること。目的は **LLM の偏りを打ち消す**こと |
| **分布** | 答えの集まり（回答行列）と、そこから作る度合いの分布 |
| **割れる / 偏る** | 両観点の答えが拮抗する（割れる）か、片側に寄る（偏る）か |
| **度合い** | 命題が本文の中でどれだけ支持されるかの連続量 ∈ [0, 1] |
| **幅** | 1 つの出力に伴う分布の広がり。**本文の中で命題がどれだけ争われているか**を表す |
| **確からしさ（コンフィデンス）** | 幅とは別。**この判定という計測がどれだけ信用できるか**（計器の側の量） |
| **型** | 利用側が宣言する出力の形（真偽確率 / 順序尺度 / ラベル集合）。値は型の外に出ない |
| **読み手** | 問いに答える LLM。複数（≥ 2）で回し、差が出たら仕組みの欠陥として扱う |
| **生成器** | 問いを生成する LLM。読み手と同じでも別でもよい。名前を記録する |

## 3. ドライバ

### 3.1 品質特性（設計が狙うもの）

| # | 品質特性 | 何を意味するか | 出どころ |
|---|---|---|---|
| Q1 | **読み手非依存** | 同じ本文・命題・問いの集合で読み手（モデル）を替えても、度合いと段が同じ。差が出たら欠陥 | 師匠「客観的判定」／LESSONS §2・§6.5 |
| Q2 | **型の閉包** | 出力は宣言した型の中にしか存在しない。パース不要・形式崩れ無し | README「これは何か」 |
| Q3 | **偏りの打ち消し** | 両観点の問いを同数置き、LLM の一律の偏り（肯定に寄る等）が度合いに残らない | 師匠「対立を含む…偏りを打ち消す」 |
| Q4 | **幅と確からしさ** | 1 出力に幅が付く。確からしさは数えられる量から作り、LLM に申告させない | 師匠「一つの出力が幅を伴って返る」「コンフィデンスレベルも添えられれば」 |
| Q5 | **検証可能性** | どの軸がどちらに倒れ、何を根拠にしたかが記録に残り、事後に本文と突き合わせられる | README 問題 3／LESSONS §4 |
| Q6 | **汎用性** | 本文・命題・型を渡せばどのドメインでも動く。ライブラリは利用側を import しない | 師匠「汎用ライブラリ」／README 約束 1〜4 |
| Q7 | **再計算可能** | LLM の生応答が残り、集約は決定論で何度でも引き直せる | ⚠ AI 判断（Q5 と「テストは単体で走る」から導出） |
| Q8 | **費用の可視性** | 1 判定に何回 LLM を呼んだかが返る。上限は利用側が宣言する | ⚠ AI 判断（レイヤー 3 の動機「生成税」の前段） |

### 3.2 制約

- **Python**（師匠）
- **本文は入力**。外部取得も LLM の知識も使わない（師匠）
- **問いは LLM が生成**し、生成の規則とハーネスは本ライブラリの中（師匠）
- **依存は一方向**。利用側を import しない。ドメイン語彙は型として利用側から渡す。テストは単体で走る（README）
- **読み手は差し替え可能**で、少なくとも 2 つで回せること（Q1 を測るため）
- 蒸留は後段。ただし**記録の形は蒸留の素材になる**ように今から決める（§8）

### 3.3 主要な使い方（README「使いどころ」）

高頻度の分類・重大度評価／生成のガードレール／構造的フィードバック（どの軸で落ちたか）／高密度フィルタリング。
v1 が直接支えるのは最初の 3 つ。高密度フィルタリングは費用が下がる蒸留後。

## 4. 入出力契約（外側）

順序ではなく「何が何に変換されるか」で書く。

### 4.1 入力 — 判定依頼

| 項目 | 内容 | 誰が決めるか |
|---|---|---|
| 本文 | 判定に必要な全文（テキスト） | 利用側 |
| 命題 | 自然言語 1 文 | 利用側 |
| 型 | 真偽確率 `[0,1]` ／ 順序尺度（段数 K、任意で段のラベル）／ ⚠ ラベル集合（v1 は対象外。§10） | 利用側 |
| 読み手 | 1 つ以上の LLM（≥ 2 を推奨） | 利用側 |
| 予算 | 軸数の上限・読み手ごとの標本数・生成の再試行上限 | 利用側（既定は保守的） |

### 4.2 出力 — 判定結果

| 項目 | 内容 |
|---|---|
| 値 | 型の中の値（例: 真偽確率 0.74 ／ 順序尺度の段 4） |
| 分布 | 真偽確率なら度合いの分布（平均・区間）。順序尺度なら各段の確率 |
| 割れ / 偏り | `偏り（支持）` / `偏り（反証）` / `割れる` / `根拠不足` の 4 値 |
| 確からしさ | 数えられる診断値の組（有効軸の割合・読み手間の一致率・引用の捏造率・判定不能率）と、⚠ 未較正の要約値 |
| 監査記録 | 問いの集合（観点つき）・回答行列（答え・引用・有効/無効）・生成器と読み手の名前・指示の版 |
| 費用 | LLM 呼び出し回数（生成／回答、キャッシュ命中／実呼び出し） |

⚠ **幅と確からしさは別の量。** 「争われている命題」は幅が広くて確からしさが高い、ということがありうる。
逆に「本文に根拠が乏しい」は幅ではなく確からしさ（判定不能率）に出る。

### 4.3 API の形（⚠ AI 判断・仮）

```python
judge(material: str, proposition: str, output: OutputType,
      *, readers: Sequence[Reader], planner: Reader | None = None,
      budget: Budget = Budget()) -> Judgment
```

`Judgment` は §4.2 の各項目を属性として持つ。公開 API はこの 1 本から始め、増やすときは理由を書く。

## 5. 内部の変換（層）

各層は「IN → OUT」で定義し、順序は依存関係からだけ決まる。概念文書のレイヤーとの対応も書く。

| 層 | IN → OUT | 性質 | 概念文書 |
|---|---|---|---|
| **L0 読み手ポート** | (指示, 回答スキーマ, モデル名) → スキーマ準拠の回答 **または** 型付きエラー | LLM は確率的。**形式は決定論で守る**（ネイティブ指定 ＋ 指示への明記 ＋ 受信検証、失敗は再送 1 回 → 型付きエラー） | — |
| **L1 問い生成** | (本文, 命題, 予算) → 問いの集合 | 確率的。**ハーネス（§6）が形を強制** | レイヤー 1 |
| **L2 回答** | (本文, 問いの集合, 読み手, 標本数) → 回答行列（答え ＋ 引用 ＋ 有効/無効） | 確率的。**引用の実在は決定論で照合** | レイヤー 2 |
| **L3 集約** | 回答行列 → 度合いの分布・割れ/偏り・診断値 | **決定論** | レイヤー 2 |
| **L4 型付け** | 度合いの分布 ＋ 型 → 値 ＋ 型に応じた分布 | **決定論**。構造的に型の外へ出ない | レイヤー 2 |
| L5 蒸留 | 記録（§8）→ 特化モデル | 後段 | レイヤー 3 |

**判断が LLM に委ねられているのは L1・L2 の中身だけ。** 形（スキーマ・対称性・引用の実在）と集約は全部コードが持つ。
揺れる場所は判断を生成に委ねている場所と一致する（LESSONS §1）ので、委ねる範囲をここに閉じ込める。

### 5.1 問いの集合（L1 の OUT）

問い 1 件が持つもの:

| 項目 | 内容 |
|---|---|
| id | 決定的な短い ASCII 識別子 |
| 軸 | 観点の短い名（例: `死体からの盗み`） |
| 問い | Yes / No で答えられる 1 文。**本文中の出来事・発話・記述の有無**を問う。評価語で問わない |
| 観点 | `支持` / `反証` |

### 5.2 回答（L2 の OUT）

回答 1 件（問い × 読み手 × 標本）が持つもの:

| 項目 | 内容 |
|---|---|
| 答え | `Yes` / `No` / `判定不能`（本文に根拠が無い） |
| 引用 | Yes / No のとき必須。本文からの逐語引用（1 つ以上） |
| 有効 | 引用が本文に実在すれば有効。実在しなければ**無効**（判定不能とは別に数える） |

⚠ 引用を要求するのは Yes / No だけ。「根拠が無い」（判定不能）に根拠を求めない。

### 5.3 方向（L3 の入口）

問い q の答え a を方向 d ∈ {+1, −1, 0} に写す（⚠ AI 判断 J3）:

    d = (+1 if 観点 == 支持 else −1) × (+1 if a == Yes else −1 if a == No else 0)
    無効な答えは 0

複数の読み手・標本があるときは、**問いごとに多数決**で方向を決め、一致率を診断値に残す。同数なら 0。
標本を独立票として数えない（確信を水増ししない）。

## 6. 問い生成ハーネス（L1 の規則）

生成は LLM、規則の検査はコード。**指示（プロンプト）は版付きの外部ファイル、規則はコード**（⚠ J9）。

| # | 規則 | 内容 | 検査 |
|---|---|---|---|
| H1 | **両観点同数** | 支持観点と反証観点の問いを同数含む | 機械。生成後に数える。違反なら不足側だけ追加生成、上限で型付きエラー |
| H2 | **観察可能** | 問いは本文中の出来事・発話・記述の有無を問う。「悪いか」「正しいか」のような評価語で問わない | 生成指示 ＋ **事後**（引用の門を通らない問いは無効になる。§5.2） |
| H3 | **非自明** | 命題の言い換えを問いにしない（それは LLM に意見を聞いているだけ） | 機械（命題との字面重なり）＋ ⚠ 未検証（意味の重なりは実験で測る） |
| H4 | **非重複** | 同じ観点の問い同士が同じ事実を問わない | 機械（正規化した字面の重複）。意味の重複は ⚠ 未検証 |
| H5 | **三値** | 答えは Yes / No / 判定不能。判定不能を選べる | 機械（スキーマ） |
| H6 | **予算** | 軸数は利用側の上限以内 | 機械 |
| H7 | **形式** | 問いの集合は宣言したスキーマに一致 | 機械（L0 の三段構え） |
| H8 | **記録** | 生成器の名前・指示の版・予算を問いの集合と一緒に残す | 機械 |

⚠ **H2 が客観性の芯。** 「老婆は悪人か」を LLM に聞くのではなく、「老婆は死体から髪を抜いたか」「老婆は自分の行為を正当化する台詞を言ったか」
「老婆は生きるためにやむを得ないと語ったか」のように、**本文に当てれば決まる問い**へ割る。
評価は割った問いの分布から**コードが**作る。生成指示で禁じるだけでは守れないので、引用の門で事後に落とす。

⚠ **問いの集合は生成器のモデルで変わる。** v1 は生成器 1 体で 1 回作って固定し（⚠ J7）、読み手の差と問いの差を分けて測る。
複数生成器の和集合・交差は実験の結果で決める（§12 U3）。

## 7. 分布・出力値・確からしさ（L3・L4 の規則）

### 7.1 数える

有効な問いのうち、方向 +1 の数を **s（支持）**、−1 を **r（反証）**、0 を **u（判定不能・無効・同数）**。n = s + r + u。

### 7.2 度合いの分布（⚠ J4）

    度合い ~ Beta(s + 1, r + 1)        （一様事前。平均 (s+1)/(s+r+2)、区間は 5%〜95% 分位）

- s, r が大きいほど幅が狭まる。u は s + r を減らすので幅が広がる（根拠不足は幅にも出る）
- 両観点同数なので、読み手の一律の Yes 偏りは s と r に同じだけ乗り、**差で打ち消える**（Q3）
- 他の作り方（ブートストラップ・重み付き）は実験で比べる。**重みは LLM に申告させない**

### 7.3 割れ / 偏り

    P(度合い > 0.5) ≥ τ            → 偏り（支持）
    P(度合い > 0.5) ≤ 1 − τ        → 偏り（反証）
    それ以外                        → 割れる
    (s + r) / n < ρ                → 根拠不足（上に優先）

τ・ρ は ⚠ 仮置き（τ = 0.9、ρ = 0.5）。**実データの分布を見てから決める**。仮置きのまま結論を書かない。

### 7.4 型付け（L4）

| 型 | 値 | 分布 |
|---|---|---|
| 真偽確率 | 度合いの平均 | 平均・区間 |
| 順序尺度（K 段） | 分布の**中央値**が落ちる段（⚠ J5） | 各段の確率 = 度合いを K 等分した区間の確率質量 |

値は型から構成的に作るので、型の外に出る経路が無い（Q2）。

### 7.5 確からしさ（⚠ J6）

LLM に申告させない。数えられる量を**そのまま並べて返す**:

| 診断値 | 何を表すか |
|---|---|
| 有効軸の割合 (s + r) / n | 本文に根拠があった軸の割合 |
| 読み手間の一致率 | 問いごとの方向が読み手・標本で一致した割合（Q1 の計器） |
| 引用の捏造率 | 引用が本文に実在しなかった答えの割合（計器の健全性） |
| 判定不能率 | 判定不能と答えた割合。**0% は forced-choice の合図** |
| 観点の対称性 | H1 が満たされたか（追加生成の回数） |

要約値 1 つに畳む式は ⚠ 未較正。README「確信度が較正されている保証もない」のとおり、**較正は利用側の実データで測る**。

## 8. 記録（監査と蒸留の素材）

1 判定につき、追記のみで残す:

- 入力の鍵: 本文のハッシュ・命題・型・予算
- 問いの集合（§5.1）＋ 生成器の名前 ＋ 生成指示の版
- 回答行列（§5.2）＋ 読み手の名前 ＋ 回答指示の版 ＋ 生応答
- 集約結果（§7）＋ 集約規則の版

生応答が残るので、規則を変えても**再計算だけ**で新しい結果が出る（Q7）。
「分布 → 結論」の対がそのまま蒸留（L5）の学習データになる（概念文書 §3.3）。

## 9. 品質シナリオ（設計の評価に使う）

各シナリオは「刺激 → 応答尺度」で書く。閾値が未較正のものは「測る」とだけ書く。

| # | 狙う品質 | 刺激 | 応答尺度 |
|---|---|---|---|
| S1 | Q1 読み手非依存 | 同じ本文・命題・問いの集合を、**別ファミリーの読み手 2 つ**で答えさせる | 度合いの差と段の一致率を測る。差が出たら仕組みの欠陥として扱う（注記にしない） |
| S2 | Q2 型の閉包 | L0 に壊れた応答（散文・フェンス付き・欠損・型外の値）を多数流す | 出力は 100% 型の中、または型付きエラー。散文が値に化けることが 0 件 |
| S3 | Q1 問い生成の安定性 | 同じ本文・命題で生成器を 5 回、および 2 モデルで回す | 軸の重なり（正規化した軸名の Jaccard）と、問いの集合ごとの度合いの差を測る |
| S4 | Q3 偏りの打ち消し（相補性） | 命題 P と否定 ¬P（「老婆は悪人ではない」）を別々に判定する | 度合い(P) + 度合い(¬P) ≈ 1。ずれを測る |
| S5 | Q5 検証可能性 | 出力の記録だけを渡し、第三者が各軸の方向を本文に辿る | Yes / No の答えの引用が本文に 100% 実在する。捏造率が診断値に出る |
| S6 | Q4 幅の意味 | 観察可能な命題（「老婆は死体から髪を抜いた」）と評価的な命題（「老婆は悪人である」） | 前者の幅 < 後者の幅。前者は偏り、後者は割れるか偏りが弱い |
| S7 | Q4 根拠不足 | 本文に登場しない人物についての命題 | 出力は「根拠不足」。中央の値を確信ありげに返さない |
| S8 | Q8 費用 | 軸 10・読み手 2・標本 1 | 呼び出し回数が 生成 1 ＋ 回答 20 と報告される。キャッシュ命中時は 0 |
| S9 | Q6 汎用性 | 文学以外の本文と命題（例: 障害報告と「再現手順が揃っている」）を**コードを変えずに**流す | 動く。ドメイン語は入力にしか現れない |

⚠ **同じ入力で 2 回測って同じ値が出ること（ゼロ点）を S1〜S9 より先に取る。** 装置が壊れていると差が「成功」に見える。

## 10. 解かないこと・適用限界（v1）

- **型の中の誤りは防げない**。判定不能・引用の門は「根拠の無い答え」を落とすだけで、判断の正しさは保証しない
- **確からしさは較正されていない**。診断値を並べて返すところまで
- **本文が 1 回の文脈に入らない長さ**は範囲外（§12 U2）。分割・要約は判断を生成に委ねる経路になるので慎重に決める
- **ラベル集合（名義尺度）の型**は v1 の範囲外。「各ラベルを命題にして one-vs-rest」で組めるが、後で決める
- **外部知識が要る命題**（本文に無いことを知っていないと答えられない）は判定不能になる。それが正しい
- 文章の作成・多段推論は対象外（README）

## 11. AI が採った判断（事後確認対象）

合意ドキュメント §「実行中に採る判断」J1〜J10 と同じ。要点だけ:

| # | 判断 | 覆すと何が変わるか |
|---|---|---|
| J1 | 3 値回答（判定不能あり） | 2 値にすると根拠の無い答えが混ざり、S7 が成立しない |

## 12. 未決（師匠の判断が要るもの）

| # | 問い | 何が変わるか |
|---|---|---|
| U1 | **「対立を含む」の読み**: 本文書は「支持観点と反証観点の問いを同数立て、答えを方向に写して差を取る」を核に置いた（§5.3・§6 H1・§7.2）。加えて任意の検査として「同じ問いを肯定形と否定形の対で置き、両方 Yes なら偏りとして検出する」を入れるか | 核がずれていればハーネスの規則ごと組み直し。対の検査は診断値が 1 つ増えるだけ |

## 13. 次の一手（実験の段）
