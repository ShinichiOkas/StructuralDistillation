### C-1 2 回目 C-2 の直しで退行した。既定の生成器では「自己交差検証」と「生成器も読み手も同じモデル」が消える

**どこ**

- `structural_distillation/compose.py:167`（`{model_of(v) for v in verifiers} == {model_of(planner)} if generated and planner is not None`）
- 同 `:179`（`same = (planner is not None and model_of(planner) in models) if generated else ...`）
- 同 `:283-284`（`_note_models(..., planner, generated=qs.source == "generated")` ——
  渡しているのは**利用側が書いた `planner` 引数**であって、実際に問いを作った生成器ではない）
- `README.md:163`（「1 モデルのときは判定に注意が付きます（`Judgment.notes`）」）
- `doc/UPSTREAM_DESIGN.md:433`（「ライブラリは 1 モデルのとき（**交差検証なし・自己交差検証・読み手が全部同じモデル**）判定に注意を出す」）

**何が問題か**

`judge()` は `planner` を省けば「偽でない読み手の先頭」を生成器にする（`compose.py:263`）。
検証役も省けば偽でない読み手全員（同 `:266`）。**つまり `judge(text, prop, out, readers=[a, b])` と書くだけで、
生成器・読み手・検証役がすべて同じモデルになる** —— これがいちばん素直な 1 モデル運用である。

ところが `_note_models` に渡っているのは解決後の生成器ではなく引数の `planner`（＝ `None`）なので:

- `:167` は `generated and planner is not None` が偽 → 名前比較に落ち、`{'#a','#b'} == {'#a'}` は偽 →
  **「検証役が生成器と同じモデル（自己交差検証）」が出ない**
- `:179` は `planner is not None and ...` が偽 → `same` が偽 → **「生成器も読み手も同じモデル」が出ない**
- `:185` の代わりの一言は `not generated` を要求するので、生成した経路では出ない

**直す前（`6344c91`）はこの経路で 3 件とも出ていた。** 旧版は `used_planner = gen`（解決後の生成器）を渡していたからである
（`git show 6344c91:structural_distillation/compose.py` の `:265`）。今回の直しで `used_planner` をやめ、
引数の `planner` をそのまま渡すようにしたため、既定の生成器という**もっとも普通の 1 モデル構成が抜け落ちた**。

**どう確かめたか**

### C-2 再利用・受け渡しの「自己交差検証」判定は、このライブラリが作れない問いの集合でしか真にならない

**どこ**

- `structural_distillation/compose.py:166-170`（`else set(qs.crosscheck.verifiers) == {qs.planner}`）
- `structural_distillation/l1.py:107`（`if budget.crosscheck and len(real_verifiers) >= 2:`）
- 同 `:184`（`CrossCheck(verifiers=[v.name for v in verifiers], ...)`）
- `structural_distillation/compose.py:270`（`if len({v.name for v in vs}) != len(vs): raise InputError`）
- `tests/test_judge.py:317-321`（`replace(gen.question_set.crosscheck, verifiers=["solo"])` で**手で組んだ**状態を当てている）
- `tools/mutation_check.py:58-59`（変異体「judge 再利用した問いの自己交差検証を見落とす」）
- `.pair-agent/agreements/single-model-operation.md:153`（対応欄「交差検証の不在は 1 か所（`_note_models`）が言う。4 経路のテストと変異体 6 個を追加」）

**何が問題か**

`set(qs.crosscheck.verifiers) == {qs.planner}` が真になるには、**検証役がちょうど 1 体で、その名前が生成器の名前と同じ**でなければならない。
しかし `l1.plan` は検証役が 2 体未満なら交差検証そのものをしない（`l1.py:107`）ので `crosscheck` は `None` になり、
2 体以上のときは `compose.py:270` が名前の重複を拒むので `crosscheck.verifiers` は必ず**相異なる 2 個以上の名前**になる。
したがって **この枝は、このライブラリが作った問いの集合に対しては絶対に真にならない**。

実際、このスプリントの走行そのもの（生成器 `qwen3.5:4b#plan`・検証役 `qwen3.5:4b#v1`/`#v2`）を保存庫から引き直すと、
自己交差検証だったという事実は注意から落ちる。2 回目の C-2 が挙げた 2 つ目の穴は**塞がっていない**。
代わりに出るのは `:186` の「この問いの集合を作った生成器は…（記録に残った名前）」だけで、**検証役については何も言わない**。
`qs.crosscheck.verifiers` に名前は残っているのに使っていない。

新しいテスト `test_a_reused_question_set_that_crosschecked_itself_is_reported` は、
`replace(..., verifiers=["solo"])` で**ライブラリが作れない `QuestionSet` を手で組んで**この枝を通している。
変異体「judge 再利用した問いの自己交差検証を見落とす」も、そのテストだけで殺される。
＝ **テストが偶然殺しているだけで、実運用の穴は素通りする**（3 回目で見るよう指示された点そのもの）。

**どう確かめたか**

実走行と同じ構成（生成器 `#plan`・検証役 `#v1`/`#v2`・読み手 `#a`/`#b`・すべて `qwen3.5:4b`）を 3 経路で走らせた:

```

   source=stored planner=qwen3.5:4b#plan 検証役=['qwen3.5:4b#v1','qwen3.5:4b#v2']
   ・ 保存された問いは生成器 qwen3.5:4b#plan が作った（今回の指定は qwen3.5:4b#a）
   ・ 読み手が全部同じモデル（qwen3.5:4b）。…
   ・ この問いの集合を作った生成器は qwen3.5:4b#plan（記録に残った名前）。…
   >> 「検証役が生成器と同じモデル」: 出ない

== 3) 問いの集合を渡す（W5 と同じ経路）      >> 「検証役が生成器と同じモデル」: 出ない
== 6b) 検証役 3 体の問いを渡す               >> 「検証役が生成器と同じモデル」: 出ない
```

「検証役が生成器と同じモデル」は 1 件も無い（W1 の `records.jsonl` 21 件にはある＝生成した経路だから）。

**どう直せば合格にできるか**（提案）

- 名前で言えることを言う: `set(qs.crosscheck.verifiers) <= (models | names)` や
  「検証役は `#v1`, `#v2`（記録に残った名前）。読み手と同じ系統なら自己交差検証になる」のように、
  生成器と同じ扱い（`:186`）に揃える
- テストから手組みの `verifiers=["solo"]` を外し、**`judge()` が作った問いの集合だけ**で当てる
