## 実行中に採る判断（AI の判断。事後確認対象）

| # | 判断 | 理由 |
|---|---|---|
| Q1 | 「同じ本文」＝ 単位化した後の単位列が同じ（文の前後の空白や改行の違いは同じとみなす）＋ 同じ単位化規則。「同じ命題」＝ 前後の空白を除いて文字列が一致 | 問いは単位列に対して作られる。見た目の空白で別物にしない。命題は 1 文字の違いでも意味が変わりうるので正規化しない |
| Q2 | 生成器・軸数・指示の版が違っても再利用する。違いはログと CLI の出力に出す | 師匠の言葉は「同じ命題と本文」。条件を足すと再利用されない場合が増え、言葉とずれる |
| Q3 | 1 本文 × 1 命題 ＝ 1 JSON ファイル（ファイル名は鍵）。本文の単位列・命題・問いの集合・交差検証の結果・生成器・作った時刻を持つ | 人が開いて読める・直せる。一覧も 1 ファイルずつ読めば済む |
| Q4 | 交差検証の結果ごと保存し、外した軸も含めて同じ問いの集合として再利用する | 再利用の目的は同じ問いで判定すること。交差検証だけ取り直すと有効な軸が変わりうる |
| Q5 | 作り直し（`regenerate`）では古いファイルを消さず、別名（`<鍵>.superseded-<時刻>.json`）で残す | 物理削除はしない（ペア固有 Skill）。前に使った問いを後から辿れる |
| Q6 | 読めないファイル（壊れた JSON・版の違い・中身と鍵の食い違い）は上書きせずエラーで止める | 黙って作り直すと、利用側が直したかもしれない問いを失う |
| Q7 | `question_set=` を直接渡したときは保存庫を見ない・保存しない | 渡された問いは利用側の持ち物 |
| Q8 | 書き込みは一時ファイル → 置き換えで一度に行う。同じ鍵に 2 つのプロセスが同時に書いたら後勝ち | 半端なファイルを残さない。排他は v1 の範囲外（キャッシュと同じ） |
| Q9 | 再利用した記録には `source="stored"` と鍵を残す | 記録から「どの問いの集合で判定したか」を辿れるように |

## 既知リスク

- 保存した問いを人が手で直すと、ハーネスの規則を満たさない問いが再利用されうる → 読み込み時は形（軸 id の重複など）だけ検める。規則の検査はしない（直した人の判断を尊重する）。文書に書く
