## 実行中に採る判断（AI の判断。事後確認対象）

| # | 判断 | 理由 |
|---|---|---|
| Q1 | 「同じ本文」＝ 単位化した後の単位列が同じ（文の前後の空白や改行の違いは同じとみなす）＋ 同じ単位化規則。「同じ命題」＝ 前後の空白を除いて文字列が一致。文の中の改行・空白・Unicode 正規化の違いは別の本文。BOM は CLI の読み込みで落とす | 問いは単位列に対して作られる。見た目の空白で別物にしない。命題は 1 文字の違いでも意味が変わりうるので正規化しない |
| Q2 | 生成器・軸数・指示の版・交差検証の有無が違っても再利用する。違いは `Judgment.notes`（記録と CLI の「# 注意:」）と WARNING のログに出す | 師匠の言葉は「同じ命題と本文」。条件を足すと再利用されない場合が増え、言葉とずれる |
| Q3 | 1 本文 × 1 命題 ＝ 1 JSON ファイル（ファイル名は鍵） | 人が開いて読める・直せる |
| Q4 | 交差検証の結果ごと保存し、外した軸も含めて同じ問いの集合として再利用する。保存された問いが交差検証していなくても、そのまま使って知らせる | 再利用の目的は同じ問いで判定すること。交差検証だけ足すと有効な軸が変わり、同じ問いでなくなる |
| Q5 | 作り直し（`regenerate`）では古いファイルを消さず、別名に写して残す。同じ時刻でも番号を足して衝突させない。生成の標本番号の起点をずらし、キャッシュ越しでも生成器を呼び直す | 物理削除はしない（ペア固有 Skill）。「作り直す」と言って前と同じ問いが返るのは名前に反する |
| Q6 | 読めないファイルは上書きせずエラーで止める | 黙って作り直すと、利用側が直したかもしれない問いを失う |
| Q7 | `question_set=` を直接渡したときは保存庫を見ない・保存しない・鍵も持たせない | 渡された問いは利用側の持ち物 |
| Q8 | **（v2 で改めた）** 書き込みは鍵ごとのロックファイルで直列化する。一時ファイル → 古いものを写す → 置き換え | v1 は「排他は範囲外」としたが、確認済みのペア固有 Skill「書き込みはロックで直列化する」（退ける＋書くの 2 段）に反していた（受入の指摘） |
| Q9 | 再利用した記録には `source="stored"` と鍵を残す | 記録から「どの問いの集合で判定したか」を辿れるように |

## 既知リスク

- 保存した問いを人が手で直すと、ハーネスの規則を満たさない問いが再利用されうる → 読み込み時は形だけ検める。文書に書いた
- ロックは同じ機械のファイルシステムを前提にする。ネットワーク越しの共有ディレクトリでの排他は確かめていない
