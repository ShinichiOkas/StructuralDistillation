# スプリントゴール

本プロジェクトのコンセプトを理解して**上流設計を固める**。
当面は LLM を用いて判断の精度を上げることが目的。専用モデル（蒸留）は先の段階。

## 0. 師匠の言葉（原文・2026-09-21）

依頼:

> 本プロジェクトのコンセプトを理解して上流設計を固めてほしい。基本的には専用モデルを作るのは先の段階として、
> 当面はLLMを用いて判断の精度を上げることが目的。

コンセプトと規則:

> このプロジェクトは、入力した命題に対して客観的判定を行うこと。そして判定出力（スカラー）を適切な分布の連続量ないし離散値として得られること。
> その方法として内部的には対立を含む複数の問いに対してLLMで答えさせ、その分布から出力値を作るというコンセプト。
> それが実現できる汎用ライブラリであること。
> 基本的なロジックの設計は他のプロジェクトを参照せずに行うこと。実際の生きたデータを用いて何か実験したいなどの場合において他のプロジェクトを参照してもよい。

例:

> 例えば「羅生門」において「老婆は悪人である」の度合いを１～５で示せ。というような命題に対して答えが出ること。

決定（AI の 3 つの問いへの回答）:

> pair-agentの初期化はしてよい。実装言語はPython。
> 羅生門は何をしたいかを明確に伝えるための例であり、基本的には判定に必要な全文を入力する（LLMの知識に頼らない）。
> 問いの集合もLLMが生成することを基本と考える。よって問いの生成ルールやそれを規定するハーネスもこのプロジェクトに含まれる。
> 適切な分布は(b) 一つの出力が幅を伴って返ることを示す。
> その分布の確からしさ、コンフィデンスレベルも添えられればなおよい。
> 対立を含むは、LLMの偏りを打ち消すことを目的とする。Y,N両方の観点から問い、Y,Nが割れるのか、偏るのかを判定する。なので軸の撮り方は命題次第。

## 前提

- 実装言語は Python
- 当面はレイヤー 1・2（問い生成・回答・集約）。蒸留は後段
- 判定に必要な全文を入力する。LLM の知識に頼らない
- 問いの集合は LLM が生成する。生成ルールとハーネスは本プロジェクトの範囲
- 1 つの出力は幅を伴って返る。確からしさ（コンフィデンス）は添えられればなおよい
- 対立を含む問い＝Y/N 両方の観点から問い、答えが割れるか偏るかを判定する。軸の取り方は命題次第
- README の設計上の約束（依存は一方向・ドメイン知識は利用側・重みは利用側・テストは単体で走る）は維持する

## 既知リスク

- 「対立を含む」の核（U1）が私の読みとずれていると、ハーネスの規則と §7.4 を組み直す
- H2（観察可能）を機械で検査する手段が無い。v1 は人が S5 で測るしかない
- 問いの集合が生成器のモデルで変わる。読み手非依存の主張が「問い生成」の段で崩れうる（S3 で測る）
- 確からしさは診断値の組のまま。要約値を求められたら未較正であることを毎回添える
- 羅生門は読み手が記憶している本文なので、S10（反事実）を先に取らないと以降の測定が汚れる
