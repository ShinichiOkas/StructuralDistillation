# スプリントゴール

有効な軸が 0 本になったときの札を「計器不良」にし、**なぜその札になったか（理由）**と、
**上位がリトライできるだけの情報**を判定に載せる。

## 0. 師匠の言葉（原文・2026-09-23 08:09）

> (b) 「計器不良」にする。ただし理由をつけて。
> 結局問いを作り直すリトライにするわけでしょ？であれば上位がリトライできるだけの情報を返す必要あり

前の問い（実装 v1 の受入 M5）: 交差検証で全軸が外れた、または渡された問いの集合に有効な軸が無いとき、
仮置きでは札が「本文に根拠が無い」だった。原因は本文ではなく問いの集合なので取り違えて見える、という指摘。

## 実行中に採る判断（AI の判断。事後確認対象）

| # | 判断 | 理由 |
|---|---|---|
| R1 | 理由は機械が読む短い英字の符号（`no_active_axes` / `invalid_evidence` / `contradictory_axes` / `low_valid_rate` / `no_definite_axis`）。人が読む文は CLI と `retry.message` に置く | 記録を機械で読む側（リトライの判断・蒸留の素材）が日本語の文を解析しなくて済む |

| R3 | 次に取る手（`action`）は 3 つ: `regenerate`（保存庫があるので作り直す）・`replan`（保存庫が無いのでもう一度判定を呼ぶ）・`supply_question_set`（問いの集合を渡されたので、渡す側が作り直す） | 上位が何をすればよいかは、問いの出どころで決まる |
| R4 | `Reading.note`（仮置きで入れた欄）は `reason` に統合する | 同じことを 2 つの欄で言わない |
| R5 | ライブラリは自動でリトライしない | 師匠の言葉「上位がリトライできるだけの情報を返す」。何回まで試すか・生成器を替えるかは用途ごとの判断 |
